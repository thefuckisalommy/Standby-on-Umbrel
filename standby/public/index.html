Bitcoin nodes

Where the app checks your transactions and broadcasts them: the address of a mempool instance — mempool.space by default, another public instance, or your own mempool on the LAN (e.g. http://192.168.1.10:8999). The primary is tried first; if it does not answer, the secondary is tried. Leave the secondary blank to use the primary alone. This is a mempool API endpoint, not an Electrum server (port 50001) and not a Bitcoin Core RPC address.

Check-in API keys

A key lets a service or app check in for you — a telegram bot, a shortcut, or even your AI assistant. A key can only record a check-in: it cannot read your transactions, broadcast anything, or change settings. Give each service its own key so you can revoke one without touching the others. The key is shown once, when it is created — copy it then.

Your connection IP is:

POST /checkin to check in, GET /health to test — the key goes as an Authorization: Bearer token.

To add it as a custom integration, use:
Name: Standby Check-in
Base URL: the connection IP above
Auth: Bearer token (Authorization: Bearer)
Test path: /health
API key / token: the key you generate below.

The check-in connection is plain HTTP — keep port 3101 on your trusted LAN and Tailscale network only; never expose it to the internet.

Data backup

Download a backup of everything needed to restore this setup: every signed transaction (hex included), your settings, and the check-in clock, plus the check-in and broadcast history. It is a plain JSON file — keep it somewhere safe. It contains the signed hexes, which reveal the destination addresses and amounts, so treat it like the transactions themselves.

The backup is not encrypted.
